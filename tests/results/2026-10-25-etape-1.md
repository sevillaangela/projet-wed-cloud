## 1. Quota de concurrence Lambda

La page [AWS Lambda endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/lambda-service.html) indique deux choses :

- le quota par défaut de « Concurrent executions » est **1 000** par région ;
- les comptes AWS récents ont un quota de concurrence et de mémoire **réduit**. AWS le relève avec l'usage, ou sur demande. La page ne publie pas le chiffre réduit. Le « 10 » cité dans le brief est un retour d'utilisateurs, pas une valeur lue sur ce compte.

Résultat sur le compte : **non mesuré**.

Commande à lancer dans la région du projet (celle d'AWS Settings) :

```bash
aws lambda get-account-settings --region LA_REGION --query 'AccountLimit.ConcurrentExecutions'
```

La documentation de la commande est [get-account-settings](https://docs.aws.amazon.com/cli/latest/reference/lambda/get-account-settings.html). Un compte ordinaire affiche `1000`. Si le nombre est bien plus bas, demander l'augmentation dans Service Quotas avant le test de pic (étape 11).

## 2. SES, bac à sable

D'après [Request production access](https://docs.aws.amazon.com/ses/latest/dg/request-production-access.html) et [Service quotas in Amazon SES](https://docs.aws.amazon.com/ses/latest/dg/quotas.html), un compte dans le bac à sable :

- n'envoie qu'à des adresses ou domaines vérifiés, ou au simulateur SES ;
- est limité à **200** messages par 24 heures et **1** message par seconde ;
- l'est **dans chaque région** séparément. Vérifier une adresse en Irlande ne la vérifie pas à Stockholm.

Résultat sur le compte : **non mesuré**. Aucune adresse n'a été vérifiée depuis ici.

Commande :

```bash
aws sesv2 get-account --region LA_REGION --query '{production:ProductionAccessEnabled,quota:SendQuota}'
```

`ProductionAccessEnabled` à `false` signifie « encore dans le bac à sable ». La description du champ est dans [get-account](https://docs.aws.amazon.com/cli/latest/reference/sesv2/get-account.html). Pour le week-end, le bac à sable suffit si l'adresse expéditrice et une adresse de test sont vérifiées dans la même région. La sortie du bac à sable n'est pas nécessaire pour les essais.

## 5. Limites WebSocket d'API Gateway

Source : [Quotas for configuring and running a WebSocket](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-execution-service-websocket-limits-table.html) et [codes de fermeture](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-websocket-api-overview.html). Aucune de ces limites n'est augmentable.

| Limite | Valeur | Si on la dépasse |
| --- | --- | --- |
| Durée de connexion | 2 heures | fermeture, code 1001 |
| Inactivité | 10 minutes | fermeture, code 1001 |
| Message | 128 Ko | fermeture, code 1009 |
| Cadre | 32 Ko | idem, il faut découper |
| Cadre binaire | interdit | fermeture, code 1003 |
| Délai d'intégration Lambda | 29 secondes | la fonction doit avoir répondu |

Le client enverra un court message texte avant les 10 minutes d'inactivité (choix prévu : toutes les 5 minutes) et se reconnectera après un 1001. Une frappe Yjs est très loin de 128 Ko. Le binaire est le point qui change le protocole : le relais parlera texte.
